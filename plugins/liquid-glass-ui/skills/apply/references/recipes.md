# Liquid Glass recipes — condensed

Source of truth: `docs/08-liquid-glass.md` §5 "Implementation Recipes", with §7's focus
strategy and §8's mitigations folded into the places they belong. Values come from §4 and
are in `tokens.md`; nothing here restates a value the token file owns.

**The ladder, before anything else.** Three tiers, gated by `@supports` and never by a
user-agent string:

| Tier | What it is | Where it runs |
|---|---|---|
| **2** | SVG displacement + blur + saturate | Chromium only — `backdrop-filter: url(#f)` is not supported in Safari or Firefox |
| **1** | blur + saturate + brightness + specular rim | Everywhere `backdrop-filter` works. This tier is glassmorphism |
| **0** | Opaque fill ≥ 0.94, border, shadow, no filter at all | Everywhere else, plus reduced transparency, increased contrast, forced colors and print |

Emit them in the order 0, 1, 2 — the least capable rung is the base declaration and each
enhancement is additive. Written the other way round, a browser that fails the test is left
with whatever the previous rule happened to leave behind.

---

## 1. Vanilla CSS — the reference implementation

### Markup

The filter `<defs>` go in the document **once**, not once per component. They are
decoration and are hidden from assistive technology: without `focusable="false"` some
assistive technology still stops on an inline `<svg>`.

```html
<!-- Generated by ../scripts/displacement-map.mjs. One <filter> per distinct
     component size; the map is a base64 data URI and is never fetched. -->
<svg width="0" height="0" aria-hidden="true" focusable="false"
     style="position:absolute;pointer-events:none">
  <defs>
    <filter id="lg-refract" x="-8.4%" y="-44.7%" width="116.8%" height="189.4%"
            filterUnits="objectBoundingBox" color-interpolation-filters="sRGB">
      <!-- Red is the horizontal offset, green the vertical, 128 is neutral. -->
      <feImage href="data:image/png;base64,…"
               x="0" y="0" width="300" height="56"
               preserveAspectRatio="none" result="map"/>
      <feDisplacementMap in="SourceGraphic" in2="map" scale="48"
                         xChannelSelector="R" yChannelSelector="G" result="displaced"/>
      <feColorMatrix in="displaced" type="saturate" values="1.35"/>
    </filter>
  </defs>
</svg>

<nav class="lg lg--bar lg--refract">
  <button class="lg-btn" type="button">Library</button>
  <button class="lg-btn" type="button" aria-current="page">Now Playing</button>
  <button class="lg-btn" type="button">Search</button>
</nav>
```

Two things about the filter region, because §8 asks for regions "as tight as the effect
allows" and that is a floor as well as a ceiling. The displacement pulls the backdrop in
from up to `scale / 2` pixels beyond the edge, so the region needs that much padding on
every side plus a pixel of slack. On a wide surface that is far tighter than §5's printed
`x="-20%" y="-20%" width="140%" height="140%"`. On a 56px-tall toolbar at scale 48 it is
much *looser* — 140% of 56px is 11.2px of headroom against a lens that reaches for 24px,
so the flat region crops the displaced result at exactly the rim the effect lives in.
`displacement-map.mjs` computes it; do not hand-write it.

Floating glass chrome is usually appended at the end of the DOM for stacking reasons and
appears at the top of the screen. Either place it in DOM order matching visual order or
wrap it in a landmark — `<nav>`, `<header>` — so it is reachable directly.

### Stylesheet

```css
         it re-opens the contrast question: re-run a11y-validate against it, and

```

`min-height` and `min-width` both come from `--lg-target-min`. Doc §5 writes a literal
`44px` on `min-height` alone; the token is what the audit checks, and an icon-only capsule
fails on width long before it fails on height.

The `will-change: backdrop-filter` that §5 puts on `.lg` is deliberately absent here.
`backdrop-filter` already forces a compositing layer; §8 allows the hint on surfaces that
actually animate and requires removing it when they stop, so it belongs on the animating
selector rather than on the base class where it pins the layer in GPU memory forever.

### The accessibility layer

All four queries, in the same `@layer`, after the tiers. Each of the first three removes
**both** spellings of the filter — §5's own fallback nulls only the unprefixed one, which
on Safari 15-17 leaves `-webkit-backdrop-filter` alive in exactly the branch whose job is
to remove it.

```css
@layer liquid-glass {
  @media (prefers-reduced-transparency: reduce) {
    .lg {
      background-color: rgba(246, 246, 248, 0.98);
      -webkit-backdrop-filter: none;
              backdrop-filter: none;
    }
    .lg::before, .lg::after { display: none; }
  }

  @media (prefers-contrast: more) {
    .lg {
      background-color: rgba(255, 255, 255, 0.92);
      border-color: rgba(0, 0, 0, 0.55);
      -webkit-backdrop-filter: blur(10px);
              backdrop-filter: blur(10px);
    }
  }

  @media (forced-colors: active) {
    .lg {
      background: Canvas;
      color: CanvasText;
      border: 1px solid CanvasText;
      -webkit-backdrop-filter: none;
              backdrop-filter: none;
      box-shadow: none;
    }
    .lg::before, .lg::after { display: none; }
    .lg-btn:focus-visible { outline: 3px solid Highlight; box-shadow: none; }
  }

  @media (prefers-reduced-motion: reduce) {

      transition-duration: 1ms;
      animation: none;
    }
    .lg-btn:active { transform: none; }
    .lg--loading::after { animation: none; opacity: 1; }
  }

  @media print {

      color: #000;

    background-color: rgba(246, 246, 248, 0.98);
    -webkit-backdrop-filter: none;
            backdrop-filter: none;
  }

}
```

### The device gate

§8: feature-gate on device and drop a tier rather than shipping a lens nobody can afford.
Refraction is also disabled below a size threshold — a 32px chip does not read as a lens
and pays the full cost.

```js
const lowEnd =
  (navigator.hardwareConcurrency ?? 8) <= 4 ||
  (navigator.deviceMemory ?? 8) <= 4 ||
  navigator.connection?.saveData === true;

const canRefract =
  !lowEnd && CSS.supports("backdrop-filter", "url(#lg-refract)");

document.documentElement.dataset.glassTier = canRefract ? "2" : lowEnd ? "0" : "1";
```

Branch the emitted CSS on `[data-glass-tier]`, never on a user-agent string. `CSS.supports`
is the runtime twin of the `@supports` rule and answers the same question.

## 2. Tailwind CSS v4

No plugin required. `../assets/tokens.theme.css` is this section already written out:
the `@theme` block, the `glass-settle` keyframes, and the `glass`, `glass-rim`,
`glass-rim-after`, `glass-refract` and `glass-tier-0` utilities. Emit that file and write
markup against it.

Three traps, all of which fail silently:

1. **`@theme` is only processed at the top level of the stylesheet.** A `@theme` nested
   inside `@media` or `@layer` is dropped by Tailwind v4 without a warning — which for the
   dark palette means the whole dark palette never emits, and for the reduced-transparency
   block means the mandatory fallback never emits. Do theme switching *outside* `@theme`,
   on ordinary selectors, over the same custom properties the utilities already read.
2. **Reference a theme token with parentheses, not brackets.** `ease-(--ease-glass)` and
   `outline-(--color-glass-accent)` are the variable syntax. The bracket form takes a
   literal, so `ease-[--ease-glass]` emits `transition-timing-function: --ease-glass` — an
   invalid value the browser drops, leaving default easing, no entrance animation and no
   focus-ring colour, with no error anywhere. Registered tokens have generated names —
   `ease-glass`, `animate-glass-settle`, `rounded-glass-control` — and those are what the
   markup should use.
3. **A percentage, an SVG filter scale and a duration have no Tailwind namespace.** They
   stay plain custom properties and are consumed with `var()`. Inventing a namespace for
   them generates utilities nobody can use.

```html
<nav class="glass glass-refract glass-rim before:glass-rim-after glass-tier-0
            flex gap-2 p-2 rounded-glass-control
            motion-safe:animate-glass-settle">
  <button class="min-h-11 min-w-11 rounded-full px-[18px] py-2.5 text-[17px] font-semibold
                 transition-colors duration-[180ms] ease-glass
                 hover:bg-white/28 active:bg-white/40
                 focus-visible:outline-3 focus-visible:outline-offset-2
                 focus-visible:outline-glass-accent">
    Library
  </button>
</nav>
```

The one-liner equivalent, if the project prefers arbitrary values over `@utility`, is
`backdrop-blur-[20px] backdrop-saturate-180 bg-white/62 border border-white/45
rounded-[26px] shadow-[0_8px_32px_rgb(0_0_0/0.12)]` — Tier 1 only. There is no arbitrary-
value form of the refraction tier, because it needs the `@supports` wrapper and the
generated filter id.

## 3. React component

TypeScript, no dependencies beyond React. It handles feature detection,
`prefers-reduced-transparency`, `prefers-reduced-motion`, forced colors, increased
contrast, the intensity knob and the pointer-tracked specular highlight.

```tsx
// LiquidGlass.tsx
import * as React from "react";

type Variant = "regular" | "clear";

export interface LiquidGlassProps extends React.HTMLAttributes<HTMLDivElement> {
  /** 0 = flat opaque card, 100 = maximum refraction and transparency. */
  intensity?: number;
  variant?: Variant;
  /** Corner radius in px. Use 999 for capsule controls. */
  radius?: number;
  /** Optional brand tint, any CSS color. Keep alpha <= 0.12. */
  tint?: string;
  /** Follow the pointer with the specular highlight. */
  trackPointer?: boolean;
  as?: keyof JSX.IntrinsicElements;
  children?: React.ReactNode;
}

const FILTER_ID = "liquid-glass-refract";

function useMediaQuery(query: string): boolean {
  const [matches, setMatches] = React.useState(false);
  React.useEffect(() => {
    const mql = window.matchMedia(query);
    const onChange = () => setMatches(mql.matches);
    onChange();
    mql.addEventListener("change", onChange);
    return () => mql.removeEventListener("change", onChange);
  }, [query]);
  return matches;
}

function useSupportsSvgBackdrop(): boolean {
  const [ok, setOk] = React.useState(false);
  React.useEffect(() => {
    setOk(
      typeof CSS !== "undefined" &&
        CSS.supports("backdrop-filter", `url(#${FILTER_ID})`)
    );
  }, []);
  return ok;
}

/** Injects the displacement filter once per document. `map` is the data URI from
 *  displacement-map.mjs; without it the component runs at Tier 1. */
export function LiquidGlassFilterDefs({
  scale = 48,
  map,
  width = 300,
  height = 56,
}: { scale?: number; map?: string; width?: number; height?: number }) {
  if (!map) return null;
  const pad = Math.ceil(Math.abs(scale) / 2) + 1;
  const px = Math.ceil((pad / width) * 1000) / 10;
  const py = Math.ceil((pad / height) * 1000) / 10;
  return (
    <svg
      width={0}
      height={0}
      aria-hidden="true"
      focusable="false"
      style={{ position: "absolute", pointerEvents: "none" }}
    >
      <defs>
        <filter
          id={FILTER_ID}
          x={`${-px}%`}
          y={`${-py}%`}
          width={`${100 + 2 * px}%`}
          height={`${100 + 2 * py}%`}
          filterUnits="objectBoundingBox"
          colorInterpolationFilters="sRGB"
        >
          <feImage
            href={map}
            x="0"
            y="0"
            width={width}
            height={height}
            preserveAspectRatio="none"
            result="map"
          />
          <feDisplacementMap
            in="SourceGraphic"
            in2="map"
            scale={scale}
            xChannelSelector="R"
            yChannelSelector="G"
            result="displaced"
          />
          <feColorMatrix in="displaced" type="saturate" values="1.35" />
        </filter>
      </defs>
    </svg>
  );
}

export function LiquidGlass({
  intensity = 60,
  variant = "regular",
  radius = 26,
  tint,
  trackPointer = false,
  as = "div",
  children,
  style,
  ...rest
}: LiquidGlassProps) {
  const Tag = as as React.ElementType;
  const ref = React.useRef<HTMLDivElement | null>(null);

  const reduceTransparency = useMediaQuery("(prefers-reduced-transparency: reduce)");
  const reduceMotion = useMediaQuery("(prefers-reduced-motion: reduce)");
  const forcedColors = useMediaQuery("(forced-colors: active)");
  const moreContrast = useMediaQuery("(prefers-contrast: more)");
  const supportsRefraction = useSupportsSvgBackdrop();

  const t = Math.min(100, Math.max(0, intensity)) / 100;
  const flat = reduceTransparency || forcedColors || moreContrast;

  // Opacity floor: never below 0.55 for `regular`, never below 0.30 for `clear`.
  const baseAlpha = variant === "clear" ? 0.30 : 0.55;
  const alpha = flat ? 0.98 : baseAlpha + (1 - baseAlpha) * (1 - t) * 0.75;
  const blur = flat ? 0 : Math.round(8 + 20 * t);
  const sat = flat ? 100 : Math.round(120 + 80 * t);

  const [spec, setSpec] = React.useState({ x: 30, y: 22 });
  const onPointerMove = React.useCallback(
    (e: React.PointerEvent<HTMLDivElement>) => {
      if (!trackPointer || reduceMotion || !ref.current) return;
      const r = ref.current.getBoundingClientRect();
      setSpec({
        x: ((e.clientX - r.left) / r.width) * 100,
        y: ((e.clientY - r.top) / r.height) * 100,
      });
    },
    [trackPointer, reduceMotion]
  );

  const backdrop = flat
    ? "none"
    : supportsRefraction && t > 0.35
      ? `url(#${FILTER_ID}) blur(${blur}px) saturate(${sat}%)`
      : `blur(${blur}px) saturate(${sat}%)`;

  const surfaceStyle: React.CSSProperties = {
    position: "relative",
    isolation: "isolate",
    borderRadius: radius,
    color: "var(--lg-fg, #1C1C1E)",
    backgroundColor: `rgba(255,255,255,${alpha.toFixed(3)})`,
    border: `1px solid rgba(255,255,255,${flat ? 0.9 : 0.45})`,
    boxShadow: flat
      ? "none"
      : "0 8px 32px rgba(0,0,0,0.12), 0 1px 2px rgba(0,0,0,0.10), inset 0 1px 0 rgba(255,255,255,0.60)",
    WebkitBackdropFilter: backdrop,
    backdropFilter: backdrop,
    contain: "paint",
    transition: reduceMotion
      ? "none"
      : "background-color 180ms cubic-bezier(0.32,0.72,0,1), box-shadow 180ms cubic-bezier(0.32,0.72,0,1)",
    ...style,
  };

  const rimStyle: React.CSSProperties = {
    position: "absolute",
    inset: 0,
    borderRadius: "inherit",
    pointerEvents: "none",
    background: `radial-gradient(120% 90% at ${spec.x}% ${spec.y}%, rgba(255,255,255,${(
      0.20 + 0.55 * t
    ).toFixed(2)}) 0%, rgba(255,255,255,0) 55%)`,
    mixBlendMode: "screen",
    opacity: flat ? 0 : 1,
  };

  const tintStyle: React.CSSProperties | undefined = tint
    ? {
        position: "absolute",
        inset: 0,
        borderRadius: "inherit",
        background: tint,
        pointerEvents: "none",
        opacity: flat ? 0 : 1,
      }
    : undefined;

  return (
    <Tag ref={ref} style={surfaceStyle} onPointerMove={onPointerMove} {...rest}>
      {tintStyle ? <span aria-hidden="true" style={tintStyle} /> : null}
      <span aria-hidden="true" style={rimStyle} />
      <span style={{ position: "relative", display: "block" }}>{children}</span>
    </Tag>
  );
}
```

Four things to say about this component when emitting it, because each is a decision a
reader will otherwise take for a bug.

- **`alpha` falls as `intensity` rises**, bottoming out on `baseAlpha`. That is the
  inversion doc §13 states and this component is the tie-breaker for; see `tokens.md` §4.
- **Refraction switches on above `t > 0.35`**, not at any positive intensity. Below that
  the lens is not visible enough to justify a displacement pass.
- **`flat` collapses three separate user preferences to one branch** — reduced
  transparency, forced colors and increased contrast — and each is a real setting a user
  turned on deliberately. Never override one, and never offer a prop that does.
- **The rim and tint are `aria-hidden` `<span>`s with `pointer-events: none`.** They are
  decorative and would otherwise be announced as empty group members.

Nesting two of these is the hard fail. The component cannot detect it for you: if a
`LiquidGlass` renders inside another `LiquidGlass`, the inner one's backdrop snapshot
contains the outer one's filtered output. Use one surface with an opaque inner card.

## 4. Native — and this is the one style where native is canonical

### SwiftUI (iOS 26+ / iOS 27, Xcode 26+)

```swift
import SwiftUI

struct GlassToolbar: View {
    @Namespace private var glassNamespace
    @State private var expanded = false
    @Environment(\.accessibilityReduceTransparency) private var reduceTransparency
    @Environment(\.accessibilityReduceMotion) private var reduceMotion

    var body: some View {
        ZStack(alignment: .bottom) {
            // Let artwork bleed under the glass chrome, so the lens has
            // something to refract.
            Image("cover")
                .resizable()
                .scaledToFill()
                .backgroundExtensionEffect()
                .ignoresSafeArea()

            GlassEffectContainer(spacing: 16) {
                HStack(spacing: 16) {
                    Button("Library") {}
                        .buttonStyle(.glass)
                        .glassEffectID("library", in: glassNamespace)

                    Button {
                        withAnimation(reduceMotion ? .none : .spring(response: 0.32,
                                                                     dampingFraction: 0.8)) {
                            expanded.toggle()
                        }
                    } label: {
                        Image(systemName: expanded ? "chevron.down" : "chevron.up")
                            .frame(width: 44, height: 44)
                    }
                    .buttonStyle(.glass)
                    .glassEffectID("toggle", in: glassNamespace)

                    if expanded {
                        Button("Search") {}
                            .buttonStyle(.glass)
                            .glassEffectID("search", in: glassNamespace)
                    }
                }
                .padding(8)
                // `.regular` adapts and needs no scrim; `.clear` requires one.
                .glassEffect(reduceTransparency ? .regular.tint(.thinMaterial.opacity(1))
                                                : .regular.interactive(),
                             in: .capsule)
            }
            .padding(.bottom, 24)
        }
    }
}
```

| API | Purpose |
|---|---|
| `.glassEffect(_:in:isEnabled:)` | Applies Liquid Glass to any view, clipped to a shape |
| `Glass.regular` / `Glass.clear` | The two variants; `.clear` needs a dimming layer beneath |
| `.interactive()` | Adds press/hover reaction — scale, highlight sweep |
| `.tint(_:)` | Brand tint applied inside the material |
| `GlassEffectContainer(spacing:)` | Shared sampling region; **required** for correct blending. Glass cannot sample other glass, so overlapping glass in separate containers renders incorrectly |
| `.glassEffectID(_:in:)` | Matched-geometry morph between glass shapes across state changes |
| `.glassEffectUnion(id:namespace:)` | Forces several shapes to render as one merged blob |
| `.buttonStyle(.glass)` / `.glassProminent` | Standard glass buttons; prefer over a manual `.glassEffect` |
| `.backgroundExtensionEffect()` | Mirrors/extends content under floating chrome |
| `.scrollEdgeEffectStyle(_:for:)` | Controls the fade where scrolling content meets glass bars |

**What this skill converts.** `.background(.ultraThinMaterial)` call sites become
`.glassEffect(_:in:)`; sibling glass views are wrapped in one `GlassEffectContainer`;
`glassEffectID`s are assigned for morph transitions; custom button styles become
`.buttonStyle(.glass)` where the sizing allows. `accessibilityReduceTransparency` and
`accessibilityReduceMotion` are read **separately** — they are separate settings and users
commonly enable only one. Any custom text colour chosen for glass is re-checked against the
opaque fallback, because the fallback is a different surface.

### UIKit and AppKit

`UIGlassEffect` (a `UIVisualEffect` subclass) with `UIVisualEffectView`,
`UIGlassContainerEffect` for grouping, and `UIButton.Configuration.glass()` /
`.prominentGlass()`. On macOS, `NSGlassEffectView` and `NSGlassEffectContainerView`.
Recompiling against the iOS 26 SDK opts you in automatically; there is no per-screen
granularity.

**Opting out** is `UIDesignRequiresCompatibility: YES` in Info.plist. It reverts bars,
toolbars, tab bars, sheets and system chrome to the pre-26 design. Apple states it is
intended for debugging and short-term migration and will be removed in the next major Xcode
release — plan migration, do not plan residency.

### React Native

`@callstack/liquid-glass` exposes `LiquidGlassView` (`effect: 'clear' | 'regular' | 'none'`,
`interactive`, `tintColor`, `colorScheme`, `animated`, `animationDuration`),
`LiquidGlassContainerView` for merging, and the `isLiquidGlassSupported` constant. It
requires Xcode 26+, React Native 0.80+ and iOS 26+, degrades to a plain `View` elsewhere,
does not work in Expo Go, and `interactive` cannot be changed after mount.

### Jetpack Compose — refuse

Not applicable as a first-class material. Google confirmed in May 2026 that Android 17 will
not adopt Liquid Glass; Material 3 Expressive extends blur and translucency in menus,
sliders and quick settings but deliberately omits refraction. If the user insists, they are
writing an AGSL `RuntimeShader` against `Modifier.graphicsLayer(renderEffect = ...)` by
hand and they own the performance and accessibility consequences. Say that before writing
it, not after.

### Design tools

**Figma** shipped a native glass effect in July 2025 — use the glass material with its
refraction and depth controls rather than stacked blur layers, and no plugin. **Framer** has
no native equivalent as of mid-2026; community workarounds layer blur plus an SVG filter in
a code component.

## 5. The focus recipe

Three concentric rings, from §7. This is not negotiable and it is not tunable: a focus ring
drawn in a single colour over glass over a photo disappears, and the whole point of the
triple ring is that at least one edge clears 3:1 against **any** backdrop.

```css
:where(.lg) :is(a, button, [role="button"], input, select, summary):focus-visible {
  outline: 3px solid var(--lg-accent);
  outline-offset: 2px;
  box-shadow: 0 0 0 5px rgba(0, 0, 0, 0.55), 0 0 0 8px rgba(255, 255, 255, 0.9);
  border-radius: inherit;
}
@media (forced-colors: active) {
  :where(.lg) :focus-visible { outline: 3px solid Highlight; box-shadow: none; }
}
```

The `outline` is the ring that carries the criterion, because `forced-colors: active`
deletes `box-shadow` and takes both halos with it. Never replace the outline with the
halos, never write `outline: none` without a replacement in the same rule set, and never
let a background-colour or opacity change stand in for the ring.

Then set `scroll-margin-top` equal to the sticky glass header's height on every focusable
target. A keyboard-focused element sitting half-visible under a translucent bar is an
SC 2.4.11 failure, not a cosmetic nit, and "partly visible through the bar" does not
satisfy the criterion.

Merged and morphing glass groups change shape but must not change accessible name, role or
focus order. Do not remove a button from the DOM mid-morph.

## 6. Component set this skill emits

Chrome only. Every one of these carries the three tiers, the four accessibility blocks, the
triple-ring focus and `contain: paint`.

| Component | Rung | Notes |
|---|---|---|
| `GlassBar` | 1 | Toolbar, tab bar, now-playing bar. Capsule radius, `position: fixed`, never a scroll container's child |
| `GlassSidebar` | 1 | Edge-to-edge; colour on the active row, not on the glass |
| `GlassSheet` | 2 | Sheet radius 38px, the `glass-settle` entrance, focus trapped |
| `GlassPopover` | 2 | Anchored, dismissible, `aria-modal` only when it really is modal |
| `GlassAlert` | 3 | Nearly opaque by design — the surface you least want unreadable |
| `GlassButton` | — | Transparent fill inside a glass bar; it is **not** its own glass surface. Giving each button its own `backdrop-filter` multiplies snapshots for no visual gain |
| `GlassFilterDefs` | — | The one inline `<svg>` per document |

**What this skill does not emit, at any intensity:** a glass `<body>` or `<main>`, a glass
card grid, a glass table, a glass chart wrapper, a glass form field, or a second refracting
surface. The first is a gradient with extra steps and the most expensive texture on the
page; the rest are on the refusal list in `anti-patterns.md`.

For a bento layout under glass, render the **grid container** as one glass surface with
opaque internal dividers. A 3×3 bento of glass tiles is nine backdrop snapshots, and it is
also nested glass the moment the container is glass too.
